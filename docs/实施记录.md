## 2. 几处产品决定

**记忆的两个开关必须分开。**
"是否从对话里猜测记忆"（`extraction_enabled`）和"是否在生成时使用记忆"
（`retrieval_enabled`）是两件事。合成一个开关会让用户没法表达"别猜新的，但已确认的可以用"。
两个开关各自独立 PATCH，并带版本号做并发保护。

**记忆必须逐条确认。**
提取出来的候选是 `proposed`，不会自动变成长期记忆。用户在聊天里点确认才转
`confirmed`。这条直接来自需求文档的"per-item consent"，实现时用提议卡片承载，
确认后就地替换成结果态，而不是把卡片留在那里让用户以为没生效。

**XP 和 Lumen 的边界要硬。**
XP 是成长刻度，只增不减、不可购买；Lumen 是获取型货币，只能挣。所以衣橱定价
一律用 Lumen，订阅不卖 XP。日任务只有三个，多了会变成打卡负担。

**安全路径不吃额度。**
危机响应、举报、导出、删除、取消订阅都不消耗每日回复额度。配额是体验闸门，
不能变成求助的障碍。

**伴侣不能主动打电话，除非这段关系已经证明过自己。**
AI 主动来电是这个产品里最容易变成骚扰的功能。所以它有两道门：一是**首次通话
必须由用户发起且超过 60 秒**，二是**账号满 72 小时**。再加上 11 条禁拨规则
（第 8 节），"伴侣想你了"这件事有代价——没被需要就不发生。

**静默不算沉默的错。**
通话里前 40% 的静默不计费，也从不因为不说话就挂断。人在想事情，AI 在旁边等，
这本来就是陪伴的一部分；把它记成"浪费的分钟"是把关系当流量算。

## 3. 动手过程中修掉的真实缺陷

这些不是"测试写得不对"，是产品真的会出问题：

| 缺陷 | 表现 | 根因 | 修法 |
| --- | --- | --- | --- |
| 面板永不关闭 | 举报提交、导出、删除账号后遮罩还盖着 | `openSheet` 里 `onClick` 返回 Promise，未 `await` 直接判真值——Promise 永远 truthy，`keep` 恒为真 | `await onClick()`，并区分"返回函数表示自行关闭" |
| 记忆开关双击 409 | 连续切两次弹出冲突错误 | `version` 在闭包里被固化，第二次用的还是旧版本 | 每次点击现读 `state.memorySettings.version`，遇 409 重取并回同步 UI |
| 跨账号记忆泄漏 | 换账号后聊天里出现上一个人的待定提议，点确认报 404 | 模块级 `proposals` 数组不随导航/退出清空 | 进聊天重取 `/memories`；登出调 `resetChatState()`；404/409 就地移除卡片 |
| 复制不可用 | 真机上点 Copy 提示"copying is blocked" | WebView 里文档未聚焦时 `navigator.clipboard` 直接 reject | 加 `execCommand('copy')` 兜底 |
| 通话结束跳错页 | 从 Space 进通话，结束却落到聊天 | `go('chat')` 写死 | 回到 `space`——从哪进回哪去 |

> 最后这条后来又被推翻了一半：现在挂断**不跳页**，原地变成收据。见第 8 节
> "通话结束不跳页"。保留这一行是因为"从哪进回哪去"仍然是其他返回路径的原则。

第 7、8 节另有这一轮修掉的六条，都在语音与对话上。

## 4. 测试怎么做的

三层，覆盖面从内到外：

1. **后端 pytest，99 条**。覆盖注册登录、年龄门、记忆状态机（含 409 并发）、
   奖励与防重复领取、配额、订阅状态机、导出与删除，以及语音的全部规则条目
   （见第 8 节）。
2. **浏览器 E2E，104 条**。除了主流程，每个页面枚举所有可交互控件逐个点击，
   没有跳转/请求/DOM 变化/toast 的记为 dead control。当前 0 个。
3. **模拟器 E2E，117 条**。跑的是装进 APK 的前后端，走 CDP 真实触摸与 IME 输入。
   另有 2000 事件的 monkey，0 crash / 0 ANR。这一层会**先读余额再挑套装**：
   演示账号 30 Lumen，按列表顺序抓到的是 35 的那件，于是"真的买下来"这条路径
   在模拟器上从来没被走过，只有"余额不足 → Not now"被走过。
4. **视觉探针，16 条**（`e2e/probe-voice-rtl.mjs`）。它不测行为，只测版式：
   390×844 下英/阿两种方向都不横向溢出、元素不越界、标签不被裁。
   行为断言和版式断言分开写，是因为两者的失败方式不一样——前者是"做了错事"，
   后者是"东西装不下"，混在一起看日志会互相淹没。
   另有一个更小的 `e2e/probe-interleave.mjs`，只做一件事：连发三句，
   断言消息角色的几何顺序是 `UAUAUA`，并留一张截图（`screenshots/probe-interleave.png`）。

### 为什么模拟器这层值得单独做

浏览器里 `element.click()` 能过的东西，在 WebView 上未必能过。实际撞到的：

- 软键盘把布局视口从 839px 压到 527px，聊天滚动区和输入框重叠，
  按"元素中心"算出的坐标落到了输入框上，点击被吞掉。
- 键盘收起不是瞬间完成的，视口高度会连续几十帧变大，按钮跟着下移；
  测量和派发之间只要隔一次 CDP 往返，坐标就失效。

所以 `e2e/cdp.mjs` 的 `tap()` 现在是：失焦 → 等视口高度连续三帧不变 →
`scrollIntoView` → 再等稳定 → 在元素内部采样多个点，取第一个真正命中的。
命中失败会抛错并报出挡住它的元素，**不会假绿**。

**别用固定 sleep 等一次网络往返。** 模拟器上的 `PATCH → loadSession → 重绘`
会比浏览器慢好几倍，`sleep(1300)` 偶尔够、偶尔不够，于是同一条断言时红时绿。
这类地方一律改成等**状态**：等 `location.hash === '#/profile' && .profile-hero`
存在，等 `#call-elapsed` 不再是 `0:00`（说明 `POST /calls` 已经回来、
`call.id` 已经就位）。

最后一条不是洁癖：挂断按钮在 `call.id` 还没回来时点了会退化成 `go('voice')`，
测试量到的就是"点了没结束"。等时钟真的开始走，断言的才是决定挂断的那一刻。

### 关于 monkey

monkey 随机会点到任何地方。有一轮结束时停在 `#/signup`、进 home 显示
"No companion yet"，看起来像 bug，实际是 monkey 点进了演示账号
`new@withyou.demo`（该账号没建伴侣），路由把它导到正确的引导步骤——
产品行为是对的，不是回归。

还有一轮 2000 事件结束时停在聊天页，输入框里挂着半句没发的 "I had a long day."，
50 条额度用掉一部分，tabbar 在 Home 上——都是 monkey 随机敲出来的状态，不是残留。

最新这一轮（带 `startNewCall` 和衣橱高亮修复的 APK）2000 事件 0 crash、0 ANR，
pid 全程未变（11868 → 11868）。结束时 monkey 恰好停在 Plus 订阅页，试用已生效
（Access until Dec 20, 2026）——它随机点到了"Subscribe"，产品照常执行；
重新拉起能回到正常页面，状态连贯，没有白屏或卡死。

**先排除环境再怀疑代码。** 有一轮模拟器 `loadavg` 到 10.67、内存只剩 300MB，
logcat 里是 `ANR in app.withyou.demo ... Killing (adj 700): bg anr`，E2E 的表现是
"按钮点了没反应"。同一份 APK 在冷启后的模拟器上 115/115 全过。所以看到成片的
"点了没反应"，先 `adb shell uptime` 和 `free -m`，再看代码。

**固定 sleep 还会制造假红。** 这一轮 `export completes` 就是：导出要先重新校验密码，
2.5 秒的 sleep 在模拟器上不够，断言读到空 toast 判失败——紧接着那张截图里
明明白白写着 "Export ready."。改成等 toast 文本出现，20/20 秒内拿到就通过。
判失败和截图互相矛盾时，先信截图，再看等待方式。

## 5. 关于"双击 index.html 打不开"

这不是 bug，是浏览器的规则：`file://` 页面的 origin 是 `null`，加载 ES module
（`<script type="module" src="js/app.js">`）一律按跨域处理并被拦掉。控制台是
`Access to script at 'file:///…/js/app.js' from origin 'null' has been blocked by CORS policy`。

处理方式：`index.html` 在模块脚本之前先判断协议，是 `file:` 就当场把转圈换成
启动说明（含命令和 `start-withyou.cmd` 的指引），不再让人对着加载动画猜。
正常入口是根目录的 `start-withyou.cmd`——它起服务、等 `/healthz` 真的返回 200
之后才开浏览器，避免落在还没起来的页面上。

> 脚本叫 `start-withyou.cmd` 而不是 `start.cmd`：`start` 是 cmd 的内建命令，
> 从命令行里叫 `start.cmd` 会先命中内建命令而不是这个文件。

## 6. 语言切换

> 这一节原写作"没做"，后来按要求补上了。下面是实际实现，以及它为什么不是
> "加个下拉框"。

### 支持哪些语言

十种，界面上按**母语名**列出（自己能读自己那一行，才能找到自己）：

`en English`、`zh 简体中文`、`zh-TW 繁體中文`、`ja 日本語`、`ko 한국어`、
`es Español`、`fr Français`、`de Deutsch`、`pt Português`、`ar العربية`（RTL）。

`normalise()` 把 `zh-CN`→`zh`、`zh-TW/HK/MO`→`zh-TW`、`pt-BR`→`pt`，
认不出的标签一律落到 `en` —— 客户端可能比服务端先支持一个语言。

### 切换怎么生效

界面是"状态的纯函数"：每个 screen 都是一次 `html\`\`` 模板求值。所以切换语言
只做三件事，**不刷新页面**：

1. `setLocale()` 更新 store、`<html lang>` / `<html dir>`，并通知监听者；
   `state.js` 注册的监听者就是 `renderApp()`，当前路由原地重绘。
2. 写 `localStorage`，重载时在首屏之前就生效（`i18n.js` 的 init 块）。
3. 已登录时 `PATCH /settings/locale`，让后端 `users.locale` 跟界面一致 ——
   回复引擎读的是这一列。

第 3 步允许失败：本机仍然换了语言，toast 说明账号没存上。要是一个网络请求
失败就把界面回滚，切换会显得像坏了。

入口有两个：欢迎页（**登录之前**就能换，读不懂英文的人不必先注册）和
「我的」页的设置组。

### 文案怎么组织

- 前端 `web/js/i18n/<code>.js`，每个 701 个键，键序与 `en.js` 完全一致，
  占位符（`{left}` / `{count}` 等）逐个对齐 —— 有断言守着
  （`node e2e/i18n-check.mjs`）。
- `t(key)`：当前语言 → 英语 → 键名本身。半翻译会退化成英语，而不是空按钮。
- `tf(key, fallback)`：当前语言 → 英语 → **服务端给的原字符串**。商店物品、
  房间、活动、心情、等级这些行是后端拥有的，服务端加了新行不能渲染成裸键名。
- 复数用 `key.one` / `key.other` + `Intl.PluralRules`。
- **可持久化的值一律保持英文**：举报原因、性格标签 id、心情/活动/物品/房间 id、
  记忆原文。只有显示串被翻译——换界面语言不该改变提交给后端的数据，也不该
  让审核队列里的举报原因变成十种语言。
- **错误也要翻译。** `apiError.<CODE>` 以接口的稳定 `code` 为键（不是英文
  message），未知 code 退化为服务端原文。这里曾经只覆盖 10 个 code，而服务端能
  产出 14 个 + 客户端 2 个（`NETWORK_ERROR` 断网、`INTERNAL_ERROR` 500 兜底）+
  `HTTP_<status>`——也就是说，"导出/删除时密码输错"（`REAUTH_REQUIRED`）和
  "衣橱 Lumen 不够"（`INSUFFICIENT_FUNDS`）恰好是中文用户会看到英文的两条路。
  现在 22 个 code 全部有译文（加上了语音引入的 `CALLS_DISABLED`、`QUOTA_EXHAUSTED`、
  `MINOR_CALL_HOURS`、`CALL_MISSED`、`RESOURCE_DELETED`、`RULE_EXPIRED` 等），
  `i18n-check.mjs` 直接扫后端源码里的 `ApiError(...)` 来比对，新增 code 漏翻译会立刻失败。
- **有一类漏是门禁抓不到的**：键存在、十种语言都有，但**调用处没传它声明的占位符**。
  这种不会让 i18n 检查失败，只会让用户看到字面量 `{name}`。
  这次真发生了三处（通话列表的"来自 {name}"、详情页眉、开始通话按钮），
  所以补了 `scripts/placeholder-scan.mjs`：扫所有 `t()`/`tf()` 调用点，把实参里的
  键名和值里的 `{…}` 对比。当前 0 个问题。它不进口 i18n 门禁——那是"字典对不对"，
  这是"调用写对没写对"，两件事。

### 后端

新增 `backend/app/locales.py`：十个语言包（开场白、共情句、追问、记忆问答、
危机台词 S001–S003、边界台词 M003、关键词表、记忆抽取正则），外加
`pack(code)` —— 把该语言覆盖在英文之上合并。缺句退化成英文，不会在生成中途
`KeyError`。

`mock_ai.compose_reply(..., locale=)` 每个分支都从同一个包里取词。**关键词表也
必须来自这个包**：拿英文关键词去匹配中文消息，所有分支都会落空，最后全部
走默认分支。

中文/日文/韩文没有词边界，`\b` 永远不触发，所以关键词用子串匹配
（`_any()`），记忆检索另外补了汉字二元组（`_tokens()`）。安全分类的正则也
扩到了 CJK/韩文/罗曼语/德语/阿拉伯语。

记忆抽取的 `_normalise()` 原来写的是 `[^a-z0-9 ]+`：中文句子会被清成空串，
两条不同的记忆变成"重复"，第二条候选被静默丢掉。改成 `[^\w]+`。

- 浏览器 E2E 新增：欢迎页登录前切到西语、个人页切到中文并断言 tabbar 文案 /

### 再次设计（第二轮）

第一版的切换器是一个"列了十个族名"的列表。能换，但有三处不对：

**一、首屏永远是英文。** 读不懂英文的人得先找到那个胶囊。现在启动时按
`navigator.languages` 的第一个可识别标签选中语言，`normalise()` 负责
`zh-CN → zh` 这类映射。关键是**这一步不写 `localStorage`**：

```js
const saved = readStored();
if (saved && isSupported(saved)) current = saved;
else { /* 按设备语言推断，但不落盘 */ }
```

"从没选过"和"选过英文"是两种状态。落盘会把前者变成后者，此后再也不会跟随
系统语言——用户把手机换成中文，App 还是英文，而且找不到原因。
真正选过之后（`setLocale` 带 `persist`）设备选择才盖过账号上的值。

加载页那句 "Opening WithYou…" 原本是写死在 HTML 里的英文，`paintBootText()`
导出了却没人调用。现在 `boot()` 第一件事就是它——语言在此时已经知道了。

**二、选择器没有告诉你在选什么。** 人选的是"伴侣在这门语言里的声音"，不是族名。
所以 `/meta` 现在每种语言返回一句**真实台词**（`locales.pack(code)["openers"][0]`
和通话开场），选择器在名字下面把那句话引出来。这句话必须来自回复引擎用的同一个
包——另起一套 demo 文案就是在承诺一种伴侣并不使用的语气。

样本行用 `lang` / `dir` 标注自己，所以阿拉伯语那行在英文界面里也是从右往左排。
十行加一句说明加 Close 要能一屏放下：行高 48px、单行省略、`Note` 收到 footer 下面。
量过 `scrollH <= clientH + 2`，浏览器和模拟器各一条断言。

**三、RTL 翻错了方向。** `[dir="rtl"] .topbar { flex-direction: row-reverse }`
叠在 `direction: rtl` 之上，把顶栏翻了第二次——返回键跑到了右边之后又被翻回左边。
实测数据：

```
before: {"flex":"row-reverse","back":[36,80],"backIsOnStartSide":false}
after:  {"flex":"row","back":[308,352],"backIsOnStartSide":true}
```

flexbox 在 RTL 下本来就把第一个子元素放在右端。所以 RTL 段现在只做**镜像字形**
（返回箭头、chevron、开关滑块）：

```css
[dir="rtl"] .topbar .back { transform: scaleX(-1); }
[dir="rtl"] .toggle[aria-checked="true"]::after { transform: translateX(-18px); }
```

开关那条是另一个坑：`inset-inline-start` 会跟随书写方向，`translateX` 不会。
只改前者、不改后者，滑块会滑出轨道。

断言也跟着改成量位置而不是看截图：返回键在 `#/privacy`（有返回键的页）上
`fromRight < fromLeft`；`profile` 上第一个 tab 的 `left` 必须大于最后一个，
证明整条 tabbar 也镜像了。

### 顺带修掉的一个真 bug（不是语言问题）

写上面那条"错误提示也要是中文"的断言时，故意输错了密码——结果导出**成功**了。
原因是 `routers/privacy.py` 的二次验证只判断"有没有传 password 字段"，从不校验
它对不对：

```python
if not payload.get("reauth_token") and not payload.get("password"):
    raise ApiError(403, "REAUTH_REQUIRED", ...)   # 只证明传了字段
```

也就是说，拿到会话 token 的人不需要知道密码就能导出全部数据、删除账号。
原来的 pytest 恰好用了正确密码，所以一直没暴露。现在改成：

```python
def require_reauth(request_body, user):
    supplied = request_body.get("password") or request_body.get("reauth_token")
    if not supplied:
        raise ApiError(403, "REAUTH_REQUIRED", "Confirm your password to continue.")
    if not verify_password(str(request_body.get("password") or ""), user["password_hash"]):
        raise ApiError(403, "REAUTH_REQUIRED", "That password doesn't match.")
```

补了 `test_t10b`：错密码 / 空密码 / 不给密码三种都必须 403，且账号仍可用。
确认过它在旧代码上会失败（不是一条永远绿的测试）。

## 7. 消息交错

用户给的截图是三条消息连发：`今天过得好长。` `你记得什么？` `你好`，然后底部
堆着三条回复，对不上号。

**根因**是一个全局的"待回复"槽位：发第二条消息时，第一条的回复节点被新的一轮
覆盖掉，而它已经写进去的内容留在原处成了一个孤立的尾巴；真正在流的那一条落到
列表末尾。于是"问题在上、答案在下"。

**修法**不是排队，是取消共享槽位。现在每条发出的消息在落库时就在**自己下面**
插一个占位气泡，那条回复只往自己的占位里流：

```js
// 一条消息一个 turn，互不相干：先在自己的节点后面插占位，再让那条回复往占位里流
const turn = newTurn(userNode);
await runTurn(turn, res.message_id);
```

`U A U A U A` 因此是结构决定的，不是时序巧合。原来那个 `#typing-host` 节点
被删掉了——它存在的唯一理由就是"同时只有一条回复"这个错误假设。

浏览器 E2E 里那条断言直接复现原 bug：连发三句不等待，然后读最后六条的角色
序列，必须完全匹配 `/^(UA){3}$/`。模拟器上再跑一遍。

### 同轮发现的三处 `{name}` 泄漏

扫占位符时发现 `voice.callInbound` / `voice.callOutbound` / `voice.startCall`
在三个调用点没传 `{ name }`，用户会看到字面量 "Calling {name}" 和
"Call {name}"。三处都修了，并留下 `scripts/placeholder-scan.mjs` 防止再来一次。

而不是调时区偏移——时区改不了星期几，也躲不过"套件跑在哪一天"这个问题。

### 几个值得记的决定

**先验证再收钱的地方只有一个方向。** `POST /calls` 只接受 `direction=outbound`，
传 inbound 直接 403。T2 来电只能由触发引擎发起——否则频率上限、禁拨表、
"首次通话必须是用户的"全都成了装饰。

**静默免计不是宽容，是分界。** 前 40% 的静默不收钱（人在想事情），超出部分收
（占着线路不说话）。收据上把这条写出来，否则用户看到两个数字对不上会以为是计费 bug。

**没有硬性挂断。** 剩余 10% 时 `warn_threshold()` 返回 `should_warn`，伴侣开口
说明并收尾。`hard_cutoff: False` 是接口里的显式字段——这不是遗漏，是设计：
一句"我们下次再聊"比"嘟"更接近这个产品。

**语音条的转写由用户自己填。** 这个版本没有 ASR，假装能转写是产品在撒谎，
而且用户会立刻发现。`askTranscript()` 在发送前问一句，填了这句语音就是一轮
对话（伴侣会接），不填也能发，只是不会有回复。注释里写明了为什么不猜。

**通话结束不跳页。** 原来的实现挂断后 `go('chat')` 或 `go('space')`，都在回答
一个不该问用户的问题。"挂断之后去哪"的正确答案是留在原地看收据。所以
`finishCall()` 用 `renderApp()` 原地重绘而不是改路由——改路由会重新执行
`beginCall()` 再拨一次号（这个坑真踩过）。

### 这一轮修掉的真实缺陷

| 缺陷 | 表现 | 根因 | 修法 |
| --- | --- | --- | --- |
| 通话顶部永远 "Calling…" | 接通一整通都写着三个点 | 顶栏标签只在路由挂载时画一次，那时还在响铃 | `paintCall()` 每次都按 `call.status` 重写 `#call-top-label` |
| 三条消息回复堆在底部 | 见第 7 节 | 全局待回复槽位 | 每条消息自带占位节点 |
| 三处显示字面量 `{name}` | "Calling {name}" | 调用点没传占位符 | 补参数 + `placeholder-scan.mjs` |
| RTL 顶栏翻两次 | 阿拉伯语下返回键跑到左边 | `direction: rtl` 之上又叠了 `row-reverse` | 删掉 `row-reverse`，只镜像字形 |
| 语言面板最后一行被裁 | 阿拉伯语那行出屏 | 十行两行文本超出 88dvh | 行高 48px、样本单行省略、收紧说明边距 |

| 购物断言假绿 | 一直 PASS，但每次跑都有一条 409 被当成"预期"写进 README | 断言用 `/Owned\|Wearing/` 匹配**整屏**文本，页面上别处的徽章就能满足它；同时它去点 45 Lumen 的套装，而测试账号只有 30 | 先读余额，挑买得起的那件；买完只读**那件**的徽章 |

### 2.2 语音重构：把"看起来完成"改成"真的会发生"

上一版的语音是规则真、声音假：计费、静默阶梯、禁拨表、收据都是真的，但通话里没有
一秒钟音频——"说话"是打字，"听见"是屏幕上一行字，波形是 CSS 动画。这一版把它改成
真音频，代价是四个新决定。

**一、先分清三档能力。** 语音条、连续语音、实时通话是三件事。我们做第三档，差异点
只有两个：声音跟着人格走，通话里说的是这个用户自己的事。竞品的音色是一长串让用户挑，
声音与人设没有必然关系；我们反过来，性格先决定语速与音高，用户只在候选里试听微调。

**二、双通道，且必须有 mock。** 设备合成零依赖但音色随系统，云端合成统一但要密钥。
两条都做，默认本地、有密钥自动切云端。关键是第三种引擎：mock 不是静音占位，而是按
文本长度与音色 id 合成真实 WAV。没有它，自动化测试只能证明"调用了接口"，证明不了
"产生了可播放的音频"——而后者才是证据。

**三、全双工要有打断，打断要有预算。** 六个状态：ringing → connecting → listening
⇄ thinking → speaking → ended，抢话走 speaking → interrupted → listening。用户起音
300ms 内必须停下播报，否则"我一开口它就停"这句承诺是空的。Mute 真的关音轨，不是换样式。

**四、记忆进入通话，但只提及不复述。** 开场白优先引用一条已确认记忆，回复可引用，
响应带 memory_used 让界面能标注。不可讲述的记忆（安全事件、举报、第三方信息）不进入
语音上下文。没有 memory_used 这个字段，我们无法验证记忆真的被用了。

### 这一轮修掉的真实缺陷

| 缺陷 | 表现 | 根因 | 修法 |
| --- | --- | --- | --- |
| 安卓装进 APK 录不了音 | 点麦克风只弹"不可用" | 清单只有 INTERNET，没有 RECORD_AUDIO；Capacitor 会运行时申请，但未声明的权限永远拿不到 | 清单加 `RECORD_AUDIO` 与 `MODIFY_AUDIO_SETTINGS` |
| 字幕开关永不生效 | 无论账号怎么设，通话里字幕都是关的 | `state.voiceSettings` 在通话页被读取，但全仓库从未赋值 | 语音设置页加载时写入 state |
| 语音条过期从未执行 | 写了 30 天保留期，实际永久保留 | 只写 `expires_at`，没有任何清理逻辑 | 加 `sweep_expired()`，每次打开语音页顺手清 |
| 通话后的语音条没有声音 | 收据后的"留言"是一段文字，点不开 | 写库时 `mime='audio/mock'`、`audio=NULL`，聊天又只给 user 消息渲染语音条 | 用该角色的音色合成真实音频并落盘；放开发送方限制 |
| 波形是装饰 | 所有语音条长得一样 | CSS keyframes，与音频无关 | 录制时采样峰值存库，气泡按峰值画柱 |
| 静音靠打字停顿 | 不说话但打字，会被当成"在说话" | 没有音频流，只能拿输入事件凑 | 改为 VAD：RMS 阈值 + 起音/尾音判定 |
| 音频塞在数据库里 | 4MB 上限，一条 5 分钟语音就可能被拒 | base64 存 TEXT 列 | 落盘存键；旧数据保持可读，不做破坏性迁移 |

这批缺陷里有三条不是"没做"，而是"做了但没生效"：字幕开关、过期清理、安卓权限。
它们的共同点是**没有任何断言盯着**——功能写了、代码跑了、界面看起来对，只有真的用
一次才会发现。这一轮补的断言都是针对这类"沉默的失效"。

### 仍然取舍

- 语音合成需要密钥或设备音色。没有时用 mock 引擎（真实 WAV，但它是电子音），
  或进入无声音状态并显示字幕；这属于部署限制，界面会写明。
- 没有 ASR 时，用户说的话被保存但不被理解，界面提示补一句文字。这是刻意的诚实降级。
- T2 主动来电的接听界面没有：后端有 `/calls/{id}/answer` 与完整契约，
  但 App 里没有来电弹窗——那需要推送通道，不在本次范围。
- 语音条 30 天过期，转写随条删除。
