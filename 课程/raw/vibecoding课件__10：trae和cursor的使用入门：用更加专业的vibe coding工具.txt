V i b e  c o d i n g 产 品 实 战
Coze编程的特点
• 适合产品经理快速把一个想法变成在线可看的 AI 应用
• 优点：
• 不需要本地环境 
• 不需要理解 npm、Python、Node.js、端口 
• 比较适合“我有一个产品想法，先做出来看看” 
• 对非技术用户友好 
• 更适合轻量 AI 应用、页面原型、可演示小工具 
• 局限：
• 项目复杂后，可控性有限 
• 本地文件、复杂工程结构、长期维护不如 IDE 类工具 
• 对真实 SaaS、后台系统、多模块工程不够自由 
• 更适合 Demo，而不是复杂产品的长期工程化开发 
• 适合产品经理的场景：
• 做一个 AI 问答应用 
• 做一个 AI 表单生成器 
• 做一个简单的 AI 工具页 
• 做课程展示、路演 Demo、概念验证

Trae
• Trae 更像是一个对新手友好的AI IDE
• 优点：
• 国内用户可能更容易上手和中文环境
• 对新手比 Cursor 更柔和
• 对产品经理做前端 Demo 比较友好
• 局限：
• 工程生态、插件生态、开发者习惯沉淀通常不如 Cursor
• 高复杂度项目中，仍然需要懂项目结构和运行逻辑
• 如果要真正上线，仍要面对依赖、环境、接口、部署问
题
• 适合产品经理的场景：
• 想做一个看起来完整的 Web Demo
• 对代码不熟，但愿意学一点本地开发
• 想从需求文档直接生成项目
• 不想一开始就被 Cursor 的工程细节劝退

V i b e  c o d i n g 产 品 实 战
Cursor
• 更接近真实开发环境的 AI IDE，适合把 Demo 做得更像一个真产品
• 优点：
• 接近真实开发者工作流 
• 适合多文件项目 
• 适合修改已有代码 
• 适合做真正可运行的产品原型 
• 可以结合 Git、终端、依赖管理、本地服务 
• 对前端项目、SaaS Demo、管理后台、AI 应用原型很强 
• 局限：
• 产品经理需要补一些工程基础 
• 本地环境容易卡住 
• 要理解“项目不是网页截图，而是一堆文件 + 依赖 + 服务” 
• 调用大模型 API 时，通常要自己配置 API Key、环境变量、后端接口 
• 适合产品经理的场景：
• 做一个能本地运行的 AI 产品 Demo 
• 做 B 端 SaaS 原型 
• 做管理后台、数据看板、AI 助手、CRM、ERP 模块 Demo 
• 做可以拿给面试官、老板、客户演示的半成品

Codex
• OpenAI 的代码执行型 Agent
• 优点：
• 适合执行明确的开发任务 
• 适合代码库修改、自动化脚本、批量改造 
• 和 OpenAI 模型生态结合紧密 
• 对懂工程的人效率高 
• 局限：
• 不适合作为产品经理的第一款 AI 编程工具 
• 对命令行、项目结构、Git、测试有要求 
• 更适合“已有代码库里完成任务”，不是“零基础可视
化做 Demo” 
• 适合产品经理的场景：
• 已经有项目代码 
• 需要让 Agent 改一个模块 
• 你能描述清楚任务，并能检查结果 
• 有开发同事协作兜底

Claude Code
• 偏工程 Agent 的强工具，适合复杂代码库和多步骤开发任
务
• 优点：
• 适合复杂代码库理解 
• 多文件修改能力强 
• 适合命令行开发者 
• 适合自动化工程任务 
• 对大型项目重构、Debug、测试、文档更新比较强 
• 局限：
• 产品经理初学门槛较高 
• 终端操作多 
• 成本、权限、安全边界都要理解 
• 不适合完全零基础用户直接上手 
• 适合产品经理的场景：
• 产品经理有一定代码基础 
• 做技术型产品、开发者工具、AI Agent 产品 
• 需要深入理解已有项目 
• 和工程团队共同推进 Demo
