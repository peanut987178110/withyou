# AI 虚拟陪伴产品 × WorkBuddy 新版课程表

## 课程主线

从一个 AI 虚拟陪伴产品的市场与用户需求出发，逐步理解并搭建：

**产品定位 → 智能体 → Prompt → RAG → Function Calling → Workflow → Skill → Agent 编排 → 测试与产品化**

## 关键概念的教学定位

| 概念 | 课程中的准确含义 | 在 AI 虚拟陪伴产品中的例子 |
|---|---|---|
| Prompt | 给模型的角色、任务、规则、示例和上下文要求 | 规定如何倾听、追问、给建议 |
| Memory | 面向用户的长期信息管理机制 | 用户确认后保存偏好、重要经历 |
| RAG | 先检索资料，再把相关内容交给模型生成 | 检索用户保存的放松清单 |
| Function Calling | 模型提出结构化工具调用请求，由应用校验并执行 | 创建提醒、查询日程、写入记录 |
| Workflow | 由多个节点组成的确定性执行流程，负责输入输出、变量、分支和失败处理 | 晚间复盘：提取事件→校验→生成摘要→用户确认→保存 |
| Skill | 按需加载的专业操作规程和资源包 | 晚间复盘 Skill、明日计划 Skill |
| Agent | 在目标、上下文和权限约束下，选择下一步行动的智能体 | 判断是聊天、检索、调用 Skill 还是调用工具 |
| MCP | 连接 AI 应用与外部工具、资源的标准化协议 | 连接日历、文件、数据库等外部服务 |

## 六周课程安排

### 第 1 周：认识赛道，定义产品问题

目标：理解为什么做 AI 虚拟陪伴产品，完成产品方向和第一版需求定义。

| 天数 | 课程主题 | 核心内容 | 当天产出 |
|---|---|---|---|
| 第 1 天 | 为什么要做 AI 虚拟陪伴产品 | 陪伴的历史；年轻人的生活场景；日本及国内外陪伴型产品；PMF；市场与用户需求 | 广义痛点、目标用户假设 |
| 第 2 天 | 从零安装 WorkBuddy | WorkBuddy 的定位；账号、模型、工作区、权限；完成第一次成功对话 | 可运行环境、第一次成功记录 |
| 第 3 天 | 看懂一款 AI 产品的全貌 | 用户旅程；页面层、能力层、执行层、数据层；普通功能与 AI 能力边界 | 产品功能地图、用户流程图 |
| 第 4 天 | 从用户访谈到需求假设 | 场景访谈、替代方案、痛点证据；区分用户原话、需求判断和产品假设 | 用户访谈提纲、需求假设表 |
| 第 5 天 | JTBD 与 MVP | 当我在什么场景；我想完成什么任务；什么结果算帮助；第一版做什么、不做什么 | JTBD、MVP 范围、验收标准 |
| 第 6 天 | 第一周产品评审 | 评审用户、场景、价值、功能边界和指标；修正不成立的假设 | 第一版产品定义、V0.1 PRD |

### 第 2 周：Prompt 与基础智能体

目标：从一个最小陪伴任务开始，理解智能体、Prompt 和对话体验设计。

| 天数 | 课程主题 | 核心内容 | 当天产出 |
|---|---|---|---|
| 第 7 天 | 最简单的智能体是什么 | 模型、Prompt、上下文、输出；智能体和普通聊天的区别 | 智能体职责说明 |
| 第 8 天 | Prompt 的基本结构 | 角色、目标、任务、规则、约束、输出格式、示例 | Prompt V1 |
| 第 9 天 | 把“陪伴感”写成行为 | 倾听、追问、共情、给选择、结束对话；避免空泛形容词 | 对话行为规范 |
| 第 10 天 | 场景拆解与对话分支 | 用户想倾诉、想建议、想复盘、想安静时分别怎么处理 | 对话状态与分支表 |
| 第 11 天 | Prompt 调试与对照测试 | 指令冲突、角色漂移、过度说教、回复重复、上下文干扰 | Prompt V2、测试集 |
| 第 12 天 | 实战：完成基础陪伴智能体 | 运行 5 个典型场景；对照验收标准修复问题 | V0.2 基础智能体 |

### 第 3 周：Memory 与 RAG

目标：区分上下文、用户记忆和知识检索，做出可控的长期连续体验。

| 天数 | 课程主题 | 核心内容 | 当天产出 |
|---|---|---|---|
| 第 13 天 | 上下文、记忆和知识库的区别 | 当前对话、历史摘要、用户长期信息、外部资料的边界 | 信息分层图 |
| 第 14 天 | 用户记忆的产品设计 | 记什么、为什么记、保存多久、谁能看、怎么改、怎么删 | 记忆字段与生命周期 |
| 第 15 天 | 记忆确认与隐私控制 | proposed / confirmed；逐条确认；撤回、删除、跨账号隔离 | 记忆状态机 |
| 第 16 天 | RAG 的原理与适用场景 | 文档切分、Embedding、检索、Top-K、上下文注入；什么时候不需要 RAG | RAG 选型表 |
| 第 17 天 | 为陪伴产品建立知识库 | 放松清单、用户资料、产品规则；检索结果与回答依据 | 第一版知识库、检索链路 |
| 第 18 天 | 实战：记忆与 RAG 评测 | 记忆错误、过期信息、检索不相关、无答案场景、回答忠实度 | V0.3、评测表 |

### 第 4 周：Function Calling、Tools 与 Skill

目标：理解模型如何请求外部动作，并把重复任务封装成可复用能力。

| 天数 | 课程主题 | 核心内容 | 当天产出 |
|---|---|---|---|
| 第 19 天 | Function Calling 的正确链路 | 模型提出工具名和参数；应用校验；函数执行；结果回传模型 | Function Calling 时序图 |
| 第 20 天 | Tool 的输入、输出与权限 | 参数校验、身份校验、用户确认、失败返回、幂等和日志 | 一个工具规格说明 |
| 第 21 天 | 实做工具：创建提醒或保存记录 | 设计接口；调用外部动作；区分“模型说成功”和“系统真的成功” | 一个可运行工具 |
| 第 22 天 | Skill 是什么 | Skill 作为按需加载的专业规程；触发描述、主体规程、脚本和模板 | Skill 目录结构、Skill 规格 |
| 第 23 天 | 实做 Skill：晚间复盘 | 输入、步骤、追问限制、输出格式、异常和验证 | 晚间复盘 Skill |
| 第 24 天 | 实做 Skill：明日小计划 | 从复盘结果生成少量行动项；与工具、记忆的关系 | V0.4、两个 Skill、一个 Tool |

### 第 5 周：Workflow 与 Agent 编排

目标：准确区分 Workflow 和 Agent，并把多个能力组成可执行的产品流程。

| 天数 | 课程主题 | 核心内容 | 当天产出 |
|---|---|---|---|
| 第 25 天 | Workflow 的正确含义 | 确定性流程；节点、输入、输出、变量、分支、循环、错误处理 | Workflow 基础图 |
| 第 26 天 | 从最终输出反推流程 | 先定义最终结果，再拆分中间产物和处理节点；单元测试每个节点 | 晚间复盘 Workflow |
| 第 27 天 | Workflow 的变量与状态 | 用户 ID、会话 ID、记忆状态、任务状态；节点间数据传递 | 状态和变量表 |
| 第 28 天 | Workflow 的分支、重试和中断 | 用户改口、信息不足、工具失败、保存失败、用户退出 | 异常路径与补偿方案 |
| 第 29 天 | Agent 与 Workflow 的关系 | Agent 负责选择；Workflow 负责确定执行；Agent 可以调用多个 Workflow | Agent 编排图 |
| 第 30 天 | 实战：完整晚间陪伴流程 | 问候→判断意图→聊天/复盘/计划→记忆或工具→结束 | V0.5、端到端流程 |

## 每周固定教学节奏

| 教学日 | 课堂动作 |
|---|---|
| 第 1 天 | 提出用户问题和产品背景 |
| 第 2 天 | 讲清概念和技术边界 |
| 第 3 天 | 拆解方案和数据结构 |
| 第 4 天 | 完成核心实现 |
| 第 5 天 | 测试异常和边界 |
| 第 6 天 | 交付版本并复盘 |

## 每期固定讲法

1. 先展示一个真实场景或失败案例。
2. 明确本期要解决的用户问题。
3. 区分产品体验、AI 能力和系统执行机制。
4. 讲清概念的准确含义和适用边界。
5. 在 WorkBuddy 或项目中完成实现。
6. 用测试用例验证，而不是只看演示效果。
7. 留下可复用的模板、图表或配置。

## 三条贯穿原则

1. **先有用户问题，再选技术。**
2. **先定义最终输出，再拆分 Workflow。**
3. **模型提出请求不等于动作已经执行，所有外部动作都要经过应用校验和真实结果确认。**
